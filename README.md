# FraudGraph

Point-in-time graph features and capacity-constrained fraud investigation.

Rank suspicious transactions for a limited investigation team, using historical relationships without leaking future fraud labels.

## Implemented

- Synthetic transactions with rare fraud, coordinated device rings and legitimate shared devices.
- Streaming account/device graph feature construction before updating each event.
- Delayed labels that become available 180 ticks after each event.
- Rules, tabular gradient boosting and graph-feature gradient boosting baselines.
- Validation-only model selection using average precision.
- Review-budget precision, recall, captured fraud and false-positive workload.
- Export investigator evidence for the top cases.

## Run

Python 3.12 recommended. From this repository root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='2'
python -m fraudgraph.cli --output reports
python -m pytest -q
```

On macOS/Linux, activate with `source .venv/bin/activate` and use `export OPENBLAS_NUM_THREADS=1`. Installing the package also provides the `fraudgraph` command. Run `python -m fraudgraph.cli --help` for options. No cloud credentials, paid services, external downloads or websites are required.

## Design and evaluation

Historical graph features count previously seen distinct accounts on a device and already-matured fraud labels. Identifiers are not numeric predictors. Train at tick 8,000 using labels matured strictly before that cutoff; validation covers 8,000–9,999; test starts at 10,000. Models are frozen after training. During validation/test, online features can incorporate earlier events and labels that have since matured, representing a live feedback system rather than a static holdout feature matrix. Select the model by validation AP. Evaluate the top 5% in each retrospective batch under a fixed review budget.

## Repository structure

- `src/fraudgraph/core.py`: reusable algorithms and simulator.
- `src/fraudgraph/cli.py`: repeatable experiment and report generation.
- `tests/`: meaningful invariants, failure cases and baseline checks.
- `reports/`: committed evidence from the seeded demo.
- `docs/`: assumptions, evaluation protocol and extension ideas.

## Limitations

The data generator deliberately contains graph-related fraud structure and cannot establish general real-world superiority. This is graph feature engineering, not a graph neural network. Shared devices can be legitimate, and investigator evidence is not causal proof or a guilt determination. Batch top-k ranking uses a complete window of scores and is not an online threshold policy. Case labels are shown only as retrospective outcomes. No analyst decisions or transactions are sent anywhere.
